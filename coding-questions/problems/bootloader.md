# Repair Bootloader Program

程序是一串 `"<op> <value>"` 指令，op 是 `plus`（累加器加上 value，再到下一条）、`next`（什么都不做，
到下一条）或 `jump`（跳到当前下标 + value）。从 `pc = 0` 开始，`pc == n` 时正常结束。

| 版本 | 要求 | 方法 |
|---|---|---|
| base | 返回第一条要被执行第二次的指令下标；正常结束返回 −1 | `firstRepeatedInstruction(instructions)` |
| FU1 | 最多有一条 jump/next 是错的，翻转它（jump ↔ next）后程序一定能结束。返回结束时的累加值；本来就能结束就返回原累加值 | `repairedAccumulator(instructions)` |

## 思路

- **base**：按规则执行，用 `seen[]` 记录执行过的指令，遇到第一条执行过的就返回。O(n)。
- **FU1：O(n)，不用每条都试**（每条都试是 O(n²)，n = 10⁵ 会超时）
  1. 先算 `canEnd[i]`：从第 i 条开始不做翻转，能不能走到 `n`。把边 `i → next(i)` 反过来，
     从 `n` 出发 BFS，一遍算完。
  2. 按原程序的路径往下走。遇到 jump/next 时，看翻转后的目标能不能走到终点；第一条能的就是要修的，
     翻转后一路跑到底。翻转点之前的路径跟原程序完全一样，所以这样找是对的。
  3. 原程序本来就能结束时，直接返回它的累加值，不做翻转。

## 容易错的地方

- `next x` 翻成 `jump x` 后目标可能小于 0 或大于 n，要检查边界。
- "本来就能结束"要先判断：如果某个翻转也能让程序结束，累加值可能不一样，题目要求返回原程序的值。
- `Integer.parseInt` 可以直接解析 `"+3"` 和 `"-2"`。
