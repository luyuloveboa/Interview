# Plant Disease Spread

`m x n` 的格子，`0` = 健康，`1` = 感染。每天所有格子同时更新：一个健康格子如果 8 个邻居里
至少有 `threshold` 个是感染的，就变成感染。

## 各版本

| 版本 | 新规则 | 方法 |
|---|---|---|
| base | 返回直到某一天没有新感染为止的天数 | `daysToStabilize(grid, threshold)` |
| FU1 | 新增 `2` = 免疫：不会被感染，也不算感染邻居 | 同上 |
| FU2 | 感染后 `recoveryDays` 天恢复成免疫，恢复后不再传染；返回直到完全稳定的天数 | `daysToStabilize(grid, threshold, recoveryDays)` |
| FU3 | 被感染那一刻，如果感染邻居数 ≥ `deathThreshold`，就是 fatal；感染期结束时死亡而不是免疫。返回 `[daysUntilEnd, deadCount]` | `epidemicWithDeath(...)` |
| FU4 | 开始前可以烧掉一整行、一整列，或者什么都不烧；返回最少死亡数 | `minDeathsWithFirebreak(...)` |

## 思路

- `cnt[r][c]` = 现在有传染性的邻居数，增量维护。每天只让前一天新感染的那批去更新邻居。
  一个健康格子的计数加到正好 `== threshold` 时，进入明天的感染名单。每个格子只会进一次，
  所以总复杂度是 O(8·m·n)。
- **FU1**：代码不用改。`2` 不是种子，所以不会给任何格子加计数；`spread` 只感染 `g == 0` 的格子。
- **FU2**：用 `waves.get(d)` 记录第 d 天感染的那批，它们在第 d+R 天恢复，恢复时做 `spread(-1)`。
  某一天没有新感染时，计数之后只会往下降，以后不可能再有新感染，所以直接返回 `day + R`。
  判断健康一定要看自己维护的 `g`，不能看原始的 `grid`；否则恢复的格子会被重复感染，
  `waves` 无限变长，导致 MLE。
- **FU3**：死亡和免疫的行为完全一样，所以只需要在感染那一刻计数。判断 fatal 的位置
  在 `+1` 之后、`-1` 之前，这时的计数正好是"前一天的状态"。
- **FU4**：烧掉的格子 = 免疫的格子（`2`）。枚举 m+n+1 种烧法，每种跑一次 FU3，总复杂度 O((m+n)·m·n)。

## 题目里没说清楚的地方

- 一开始的种子也可能是 fatal 的：开局时周围已感染的格子数 ≥ `deathThreshold` 的话就算。
  FU4 例 3 要得到 5 必须这样算，不这样算答案是 2。
- 两个例子的解释和 8 邻居规则不一致，但输出是对的：
  FU1 例 1 里 (2,1) 第 2 天就感染了；FU4 例 1 里 (0,2) 是第 2 天才感染的。
