# Generate Function Profiling Events

采样 profiler 定期记录一个线程的调用栈：`samples[i] = "<time>:<stack>"`，`stack` 用 `->` 连接，
从最外层到最内层，可以为空（`"42:"`）。把相邻两次采样的差异转成事件列表 `"start|end:<time>:<function>"`。

| 版本 | 规则 | 方法 |
|---|---|---|
| base | 和上一个栈的公共前缀之后：上一个栈里的帧 `end`（从内到外），当前栈里的帧 `start`（从外到内） | `generateEvents(samples)` |
| FU1 | 调用路径 = 从根开始的前缀。连续出现 `n` 次才算有效；`start` 用这段连续出现的第一次的时间，`end` 用有效之后第一次消失的时间 | `generateEvents(samples, n)` |
| FU2 | 调用路径改成从叶子往上的**后缀**：`A->B->C` 和 `X->B->C` 共享 `B->C`。防抖规则同 FU1，比较用最长公共后缀 | `generateEvents(samples, n)` |

## 思路

- **base**：逐帧比较求公共前缀长度 `k`。先输出 `prev[len-1 .. k]` 的 `end`，再输出 `cur[k ..]` 的 `start`。
  递归（`a->b->a`）不用特殊处理，按位置比较，每个位置本来就是一个独立的帧。
  空栈要单独处理：`"".split("->")` 返回 `[""]` 而不是空数组。
- **FU1**
  - 关键观察：当前栈深度 `i` 的前缀路径和上一个样本里的是同一条路径，**当且仅当 `i < 公共前缀长度`**。
    所以每条路径的状态（连续次数 `streak`、开始时间 `start`）可以按深度存在数组里，不需要用字符串当 key。
    `streak[i] = i < cp ? prevStreak[i] + 1 : 1`。
  - 子路径出现时父路径一定出现，所以 `streak` 随深度单调不增，有效路径（`streak >= n`）一定是栈的一个前缀
    `cur[0 .. valid)`。
  - 然后就变回 base：拿"有效栈"代替原始栈做比较。前后都有效的部分长度是 `k = min(cp, prevValid)`
    （同一路径，并且上一次已经有效），`end` 输出 `prev[prevValid-1 .. k]`，`start` 输出 `cur[k .. valid)`，时间用各自的 `start[i]`。
  - `n = 1` 时就是 base，测试里也对拍了这一点。每个样本 O(栈深)。
- **FU2**：FU1 的镜像。公共前缀换成公共后缀，数组按"后缀长度"索引（后缀 `j` 的最外层帧是 `stack[len-1-j]`）。
  有效后缀一定是长度 `1 .. valid`。`end` 从最短的后缀开始（最内层），`start` 从最长的后缀开始（最外层）。
  注意：叶子一变，所有后缀都变成新路径；而根变了只影响最长的那个后缀（例 1 的 `taskA -> taskB`）。
- 同一个样本里先输出所有 `end`，再输出 `start`（FU1 例 1 的 `end:4:A, start:4:B`）。
- 事件按产生的顺序输出：FU1 / FU2 的 `start` 是在路径**变成有效**的那个样本里输出的，时间戳却是更早的连续开始时间。

## 题目里没说清楚的地方

- FU1 说路径"出现在栈里任何位置"就算出现。对"从根开始的前缀路径"来说，这就是"当前栈以它开头"。
  同理 FU2 里后缀出现 = 当前栈以它结尾。
- 同一时间戳下 `end` 和 `start` 的先后顺序题目没明说，按 FU1 例 1 取先 `end` 后 `start`。
- FU2 例 3 里 30 时刻栈是 `main->process->flush`，`main`、`process` 虽然还在栈上，但它们所在的后缀
  （`main->process->flush`、`process->flush`）是新路径，所以也要 `end`，40 时刻重新计数。这是后缀身份的直接后果，不是笔误。
